# Курсовая работа: три кроссплатформенных приложения на Flutter

## Общая цель

В курсовой работе разработаны три графических приложения. В исходном задании указана библиотека Qt, но реализация выполнена на Flutter по согласованию с преподавателем. Flutter также является кроссплатформенным фреймворком: один код на Dart можно собрать под Windows и Android.

Проекты находятся в отдельных папках:

- `zadanie_1_files` - работа с файлами JSON и структурированными данными ресторана.
- `zadanie_2_class_diagram` - построение диаграммы наследования по `.h` файлу.
- `zadanie_3_udp_chat` - UDP-чат с журналированием сообщений в SQLite.

Целевые платформы: Windows и Android.

## Задание 1. Работа с файлами

Приложение хранит список блюд ресторана. Каждая запись содержит:

- `id` - номер записи;
- `name` - название блюда;
- `category` - категория;
- `price` - цена;
- `ingredients` - список ингредиентов.

В интерфейсе есть таблица и функции:

- добавить блюдо;
- изменить блюдо;
- удалить блюдо;
- сохранить все данные в JSON;
- загрузить данные из JSON.

В Qt по варианту требовался контейнер `QVector`. Во Flutter используется стандартный список Dart `List<Dish>`. По назначению он выполняет ту же роль: хранит набор объектов одной сущности и позволяет добавлять, удалять и изменять элементы.

Для JSON во Flutter используются стандартные функции Dart:

- `jsonEncode`;
- `jsonDecode`;
- `JsonEncoder.withIndent`.

Для выбора файла используется пакет `file_picker`, который открывает системное окно выбора файла на Windows и Android.

## Задание 2. Отрисовка структуры данных

Приложение принимает на вход C++ заголовочный файл `.h` или `.hpp` и ищет объявления классов и структур. Поддерживается простой формат:

```cpp
class Person {};
class Student : public Person {};
class Teacher : public Person {};
```

После чтения файла приложение строит схему наследования:

- базовые классы располагаются выше;
- наследники располагаются ниже;
- между ними проводятся линии;
- блоки классов имеют фиксированный размер и отступы, поэтому не накладываются друг на друга.

Для отрисовки используется `CustomPainter`. Это ближайший аналог идеи `QPainter` из Qt: разработчик получает объект `Canvas` и рисует линии, прямоугольники и текст вручную.

Для удобства просмотра диаграмма помещена в `InteractiveViewer`, поэтому ее можно двигать и масштабировать.

## Задание 3. UDP-чат и база данных

Приложение работает как клиент и сервер одновременно:

- слушает локальный UDP-порт;
- отправляет сообщения на адрес и порт собеседника;
- принимает входящие UDP-пакеты;
- сохраняет все входящие и исходящие сообщения в SQLite.

Параметры можно передать при запуске:

```powershell
--db=C:\Temp\chat1.db --local-port=5001 --remote-host=127.0.0.1 --remote-port=5002
```

Таблица базы данных:

```sql
CREATE TABLE IF NOT EXISTS messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  direction TEXT NOT NULL,
  peer_host TEXT NOT NULL,
  peer_port INTEGER NOT NULL,
  text TEXT NOT NULL,
  created_at TEXT NOT NULL
);
```

Во Flutter UDP реализован через `RawDatagramSocket` из `dart:io`. В Qt для такой задачи обычно использовался бы `QUdpSocket`.

Для БД используется пакет `sqlite3`. В Qt похожая задача обычно решалась бы через модуль Qt SQL.

## Итог

Все три приложения выполнены как самостоятельные Flutter-проекты. Они используют простую структуру без сложных архитектурных шаблонов: основной экран реализован через `StatefulWidget`, данные хранятся в обычных классах Dart, а логика находится рядом с интерфейсом. Такой подход подходит для учебной курсовой работы и остается понятным при защите.
