# Процесс разработки

## 1. Создание проектов

В корневой папке `kursov` были созданы три отдельных Flutter-проекта:

```powershell
flutter create --platforms=windows,android zadanie_1_files
flutter create --platforms=windows,android zadanie_2_class_diagram
flutter create --platforms=windows,android zadanie_3_udp_chat
```

Такое разделение соответствует заданию: каждая задача оформлена отдельной программой.

## 2. Настройка зависимостей

Для задания 1 и 2 добавлен пакет `file_picker`, потому что пользователю нужно выбирать файлы через системное окно.

```powershell
flutter pub add file_picker
```

Для задания 3 добавлены пакеты для SQLite и пути к файлам:

```powershell
flutter pub add sqlite3 sqlite3_flutter_libs path_provider path
```

## 3. Реализация моделей данных

В задании 1 создан класс `Dish`, который описывает блюдо ресторана. Он умеет преобразовываться в JSON и создаваться из JSON.

В задании 2 создан класс `ClassInfo`, который хранит имя класса и список базовых классов.

В задании 3 создан класс `MessageRecord`, который хранит одно сообщение чата: направление, адрес собеседника, порт, текст и дату.

## 4. Реализация интерфейса

Все приложения сделаны через обычный `StatefulWidget`.

Причина: для курсовой работы не нужен сложный шаблон вроде BLoC или Provider. Данных немного, экран один, состояние удобно хранить прямо в классе экрана.

## 5. Файловый ввод-вывод

В задании 1 пользователь выбирает JSON-файл или место сохранения через `file_picker`.

Сохранение происходит так:

1. список `List<Dish>` преобразуется в JSON;
2. JSON кодируется в байты UTF-8;
3. байты передаются в `FilePicker.saveFile`.

Загрузка происходит так:

1. пользователь выбирает JSON-файл;
2. приложение читает текст файла;
3. `jsonDecode` преобразует текст в структуру Dart;
4. из данных создаются объекты `Dish`.

## 6. Графическая отрисовка

В задании 2 файл `.h` читается как обычный текст. Затем регулярное выражение ищет объявления `class` и `struct`.

После этого строится простая схема уровней:

- класс без базового класса находится на верхнем уровне;
- наследник размещается на уровень ниже;
- каждый уровень рисуется отдельной строкой.

Отрисовка сделана через `CustomPainter`, где вручную рисуются прямоугольники, текст и линии.

## 7. UDP-сеть

В задании 3 используется `RawDatagramSocket`.

Алгоритм работы:

1. пользователь задает локальный порт;
2. приложение открывает UDP-сокет на этом порту;
3. входящие datagram-пакеты читаются в обработчике события `RawSocketEvent.read`;
4. исходящее сообщение кодируется в UTF-8 и отправляется на адрес и порт собеседника.

Так как UDP не устанавливает постоянное соединение, каждое приложение просто знает адрес и порт второго приложения.

## 8. Подключение SQLite

При запуске чата открывается файл SQLite. Если таблицы `messages` еще нет, она создается автоматически.

Каждое входящее и исходящее сообщение сохраняется с полями:

- направление;
- адрес собеседника;
- порт собеседника;
- текст;
- дата и время.

## 9. Проверка

Для каждого проекта предполагается проверка:

```powershell
flutter analyze
flutter test
flutter build windows
flutter build apk --debug
```

Ручная проверка:

- задание 1: добавить, изменить, удалить блюдо, сохранить и загрузить JSON;
- задание 2: открыть `.h` файл и проверить диаграмму;
- задание 3: запустить два экземпляра чата на разных портах и обменяться сообщениями.
